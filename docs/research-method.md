# GPT-6 额度异常归因：预先声明的观察性方法 v1

方法 ID：`log-capacity-loco/1`；传输：`codex-cost-study/1`。
机器可读的固定规则见 `protocol/method.json`，SHA-256 随每份报告提交。不同版本或不同摘要的结果拒绝混合。此实现是项目自己的探索性模型比较程序，不是复刻 OpenAI 内部计量，不自动修改运营计费。

## 问题与“正常”

“正常”不是要求 GPT-6 与 GPT-5.6 每次请求的美元金额相等。请求长度、缓存与输出不同，本来就应有差异。我们的操作性定义是：**用某组候选分项倍率换算后，同一账号同一周期的有效成本 / 原始额度消耗，能用不依赖模型构成的平滑容量变化来解释**。需要修正的分项若随使用构成变化而造成跳变，合适的候选应在未用于拟合的周期上更好地解释数据。

不使用 Sub2Pool 当前整体 1.8 修正后的金额，也不把已有粒子滤波估计容量当标签。两者可能已经含待研究偏差，使用它们会循环论证。研究直接读取不可变的原始请求成本与原始额度百分比。

研究得到的是**相对于本地网关原价的经验修正解释**。自定义价卡、账号等级变化、未采集用量和平台内部计量变化，都可能产生相同现象；没有外部实验不能定位某段平台代码。

## 入选标准与快照对齐

研究窗口为最近 90 天；仅纳管且启用的 Sub2API 账号。默认关闭，不主动调用模型或额外从上游抓历史。明确授权后，在现有采集路径保存上游 `input_cost`、`cache_creation_cost`、`cache_read_cost`、`output_cost`，它们是事实，不是根据猜测价卡计算的分项。升级前缺失分项不补造。

使用上游实际快照的 `sampled_at`；被动轮询本机时间不能代替额度测量时间。直查没有独立时间时可使用直查时刻。对齐两个额度快照间的半开区间 `[start,end)`，要求原始捕获连续覆盖，去重并验证原始请求，时间边界精确裁剪。

v1 只接受普通档位、非长上下文、仅包含 GPT-5.6/GPT-6 的区间。任一请求模型不符、档位不符、缺少分项、分项和不能在舍入误差内对上原始标准成本，**排除整个区间**，不能只扔掉坏请求而保留全部额度消耗。明确的长上下文 false 标记优先；缺标记时必须有完整输入/缓存 Token 且总和不超过 272000。零成本缓存仍是已知 0，缺字段不是 0。

合并相邻额度观测，直到达到至少 3 个百分点且时间不超过 6 小时。重置、负增量、饱和 100%、快照冲突不能进入普通块。每周期至少 8 个块、两模型族各至少 10 次请求。至少 2 个周期、24 个块、200 次总请求、两族各 50 次才尝试归因。小块整数误差过大，这些门槛是保守设计参数，**不是保证足够统计功效的定理**。

人工排除测量会被尊重；由已有成本模型产生的自动排除不作为科研真值。管理员还须确认同一额度池没有网页端/别处调用消耗，未确认的摘要只计规模，不参与排名。这个确认无法由匿名服务独立核实。

资源保护：每次最多100账号、每账号16000观测和14周期、每块50000条原始请求。触及边界计入排除计数；不是悄悄把不完整数据当完整。所有贡献量只统计合格块，**不是安装的全部使用量**。

## 候选、容量模型与整数观测

令一个块的 GPT-5.6 标准成本为 b，GPT-6 四个成本分项为 x=(输入,缓存创建,缓存读,输出)，观察到的额度增量为 d（百分点）。对候选正倍率向量 m：

```
C(m) = b + x · m
z(m) = log(C(m) / (d / 100))
```

`z` 是候选下单位全额度的对数成本。假设同一账号周期的潜在 log 容量作随机游走，未知初始容量不设为所有账号相同。取相邻块的差分 `D z` 消去该周期初值。

上游整数百分比量化的端点误差近似均匀，方差为 1/12 pp²。线性化后，块的观测协方差：

```
R[j,j] = 1/(6 d[j]²) + 0.03²
R[j,j+1] = -1/(12 d[j] d[j+1])  # 仅当共享同一时间端点
S(q) = D R D' + diag(q² Δt)
Dz ~ Normal(0, S(q))
```

Δt 是块中心时间差（小时），下限0.01。给所有候选相同的容量波动先验：q ∈ {0.03,0.10,0.30}，均匀权重，分别代表每√小时的 log容量标准差。对其边缘化，而不是让一个模型独享更灵活的容量噪声。这里的随机游走与整数误差线性化都是近似；不声称精确描述订阅。

四分项主网格 {0.5,1,1.5,1.75,2,3}⁴，并为单项和整体候选补充1.25、1.8、2.5，共1311个向量。预先分为七类：不额外修正、整体、缓存读、缓存创建、输出、输入、非等倍率混合。整体与单项不再重复分入混合；每一族内部采用均匀离散先验。

## 样本外比较与支持度

每次留出**整个账号周期**。其他周期的似然更新本族内部的参数权重，然后对留出周期计算边缘预测分数，按对比点数量归一化。记录相对“不额外修正”的增益，限制在[-4,4]，避免一个异常周期无限控制报告。不使用训练集上最优残差来奖励试了更多向量的混合模型。

本地按周期做1024次指数权重 Bayesian bootstrap，比较七族平均预测得分。精确并列拆分票数。只传各族评分均值、7×7协方差、支持度、代表性参数均值和规模/质量摘要，不传逐周期评分或时间序列。

公共端**不直接平均或连乘用户支持度**：每个随机安装键只保留最新滚动摘要，按安装做1024次指数权重重抽样；每安装权重最多10个周期；按上传协方差/周期数加入小样本 Student-t 扰动。公开每族胜出占比及评分90%区间。至少3个合格安装才显示。这是有限汇总信息下的两级不确定性近似，不等同于获取所有原始数据后完整重拟合。

重要：留出评分共享训练数据，简单周期重抽样不完全消除依赖；同一账号多个周期亦可能相关。中央按安装分组缓和依赖，但不能证明贡献独立。支持度不是校准的真实机制后验概率或因果置信度。代表倍率是本族离散后验均值再按安装汇总，不是全局联合后验或推荐价格。

设计背景可参阅作者维护的 [交叉验证 FAQ](https://users.aalto.fi/~ave/modelselection/CV-FAQ.html) 与 [Yao 等：预测模型组合](https://arxiv.org/abs/1704.02030)。本实现不声称实现 PSIS-LOO 或 stacking；采用的是显式周期留出、预声明网格、分组预测比较。

## 不可识别、敏感性与反例

分项占比差分构成设计矩阵。通过奇异值与将每一分项对其他分项残差化检查可区分性；矩阵阈值 max(0.03,最大奇异值×0.02)、各分项有效变动范数>0.05。发生共线时停止归因，而不是给缓存读/输入任意选一个。

若所有变化集中在前三个对比点（>60%设计能量）或周期内 GPT-6 总占比标准差都<0.05，则停止归因。只有一次模型切换，恰好同时发生额度策略调整，无法区分原因。只有 GPT-6 的独立周期也无法把整体倍率与容量缩放分开，故需要同周期基线。

所有候选在最大波动假设下的最佳归一化残差平方，中位数仍>4时显示 `model_mismatch`。三个容量先验分别评估，若出现支持度>65%的不同赢家则显示 `drift_sensitive`。这些检查是预声明告警，不是精确的显著性检验。

如果不同贡献来源显著偏向不同的前两名解释（差分>2个估计标准误+0.01），公开 `heterogeneous`。不会掩盖分歧只给一个高置信度结论。

仍无法排除：跟随模型构成变化的容量策略、自定义定价、长期非平滑容量、遗漏使用、不同代理配置、超出网格的机制、匿名伪造、多安装共享同一账号。平台签名验证只说明同一键控制者提交了数据，**不是统计真实性、真人唯一性或正确采集的证明**。请求总次数不能当作独立样本数；有效推断单位是周期及安装。

## 可复现验证

Sub2Pool 提供 `scripts/research_simulation.py`。模拟原始整数百分比、变化容量、不同模型混合与已知分项倍率，分别检查整体、各单项、混合、无异常和多种漂移；还测试共线、单一构成、样本不足与所有模型不适配。CI保存合成结果，不把它混入公共贡献。

```
cd backend
uv run python ../scripts/research_simulation.py --seeds 5 --output /tmp/research-synthetic.json
```

不能用在假设成立的生成器上的高恢复率证明真实世界因果正确。研究版本修改门槛、先验、网格、算法或聚合方式时，必须升级方法ID/descriptor及互操作样例，并分开旧方法数据。

### 本次固定种子的实测结果（纯合成）

五种子 × 七种已知机制 × 三档容量漂移，共105个模拟；每个模拟5周期、每周期20块。

| 真实漂移SD / √小时 | 可给探索性结果 | 最高支持族与生成机制一致 | 敏感性拒绝 |
|---|---:|---:|---:|
| 0.025 | 32/35 | 32/35 | 3/35 |
| 0.10 | 34/35 | 32/35 | 1/35 |
| 0.30 | 33/35 | 24/35 | 2/35 |

在最高漂移档，混合机制的第5号种子被“只修缓存读”以96.4%的预测支持选中，遗漏了较弱的输入倍率。这是**高预测支持不等于真实机制被正确识别**的具体反例，不应隐藏。该方法在高噪声下可能偏向预测更稳健但不完整的简单解释；公开百分比只能解释为候选预测排名。样本外比较并不自动消除观察性混杂或模型不确定性。

原始模拟结果随仓库保存，CLI可重跑；不是任何真实OpenAI计量的研究发现，也未提交到贡献数据库。
