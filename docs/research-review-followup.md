# PR #4 复核补充：科研身份与边缘行为


## 导入备份与科研身份恢复

数据库导入始终关闭科研共创、撤销授权、清理任务租约/调度和可重算的本地摘要，不删除原始请求或成本分项。科研签名身份由当前 `DJANGO_SECRET_KEY` 加密：

- 同密钥且身份完整可解密时，保留原身份、报告 revision 和已发送记录，以便恢复后继续去重；再次发送仍需重新授权。
- 跨密钥、密文损坏或种子格式不正确时，只清理不可用的科研身份及其发送 revision、时间、摘要和接收端点，显示重置告知。管理员重新授权后才生成新身份；导入本身不联网或自动发送。
- 新身份不能与原身份去重。接收网站上的已有贡献仍按长期保留规则保存，跨实例重新贡献可能与原身份统计重叠。

正常运行中发现签名身份不可用时不会偷偷换身份，而是报告具体的发送错误。保留故障身份，便于恢复原密钥后继续使用。以上仅针对科研身份，不改变 Sub2API 等其他敏感配置的密钥恢复要求。

### 未达质量门槛的统计仍可能被保存

达到最小上报请求量但 `eligible=false` 的汇总仍可用于贡献规模和质量统计。早期返回的 `insufficient_data`、`unidentifiable` 报告保留零评分与单位倍率；后期被标记为 `external_usage_uncontrolled`、`drift_sensitive` 或 `model_mismatch` 的报告可能保留非零评分/协方差及候选倍率诊断，但支持度为零。接收端保存这些诊断，却只将 `eligible=true` 的报告用于原因支持度和倍率汇总。“不展示结论”不等于“不存储任何诊断数组”；本次复核没有修改此协议或算法。
