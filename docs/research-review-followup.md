# PR #4 复核补充：科研身份与边缘行为


## 导入备份与科研身份恢复

数据库导入始终关闭科研共创、撤销授权、清理任务租约/调度和可重算的本地摘要，不删除原始请求或成本分项。科研签名身份由当前 `DJANGO_SECRET_KEY` 加密：

- 同密钥且身份完整可解密时，保留原身份、报告 revision 和已发送记录，以便去重和明确撤回；恢复后发送仍需重新授权。
- 跨密钥、密文损坏或种子格式不正确时，只清理不可用的科研身份及其发送 revision/时间/摘要/接收端点，显示重置告知，不显示无法执行的旧端点撤回入口。管理员重新授权且达到上报门槛后才生成新身份；导入本身不联网、不自动发送或撤回。
- 新身份不能撤回原身份贡献。旧贡献须在原实例撤回，或使用原密钥和备份恢复后撤回；单纯清理本地状态不等于删除接收站点已有记录。跨实例重新贡献可能暂时与旧身份统计重叠，迁移前应先撤回旧贡献。

正常运行中发现签名身份不可用时不会偷偷换身份，而是报告具体的发送错误。明确撤回即使因密钥损坏而无法签名，也先持久化“停止后续发送”，不会因事务回滚恢复已开启状态。保留故障身份及旧端点，便于恢复原密钥后重试。以上仅针对科研身份，不改变 Sub2API 等其他敏感配置的密钥恢复要求。

### 未达质量门槛的统计仍可能被保存

达到最小上报请求量但 `eligible=false` 的汇总仍可用于贡献规模和质量统计。早期返回的 `insufficient_data`、`unidentifiable` 报告保留零评分与单位倍率；后期被标记为 `external_usage_uncontrolled`、`drift_sensitive` 或 `model_mismatch` 的报告可能保留非零评分/协方差及候选倍率诊断，但支持度为零。接收端保存这些诊断，却只将 `eligible=true` 的报告用于原因支持度和倍率汇总。“不展示结论”不等于“不存储任何诊断数组”；本次复核没有修改此协议或算法。
