# 数据与重放

本文定义额度算法可读取和可改写的数据边界。

## 原始事实

以下数据一经采集不得由额度算法修改：

- 观测时间、账号 ID、官方窗口时长和重置时间；
- 上游返回的整数已用百分比；
- Sub2API 返回的总标准成本、实际成本及其实际查询起止时间；
- 每个 Sub2API 用户的累计标准成本、实际成本及其查询窗口；
- 用户余额；
- FAST 请求修正事实；
- 管理员设置的人工起点、排除和恢复操作。

数据库中的主要载体是 `Observation`、`Sub2APIUserUsageSample` 及各观测的 `ParticipantSnapshot.raw_*` 字段。

## 派生结果

以下内容可随算法版本重新生成：

- 归属区间内成本和百分比；
- 当前等效周限和美元/1%；
- 参与者累计归属、剩余权益和余额建议；
- 概率区间、确定性范围和模型诊断；
- 面向页面的说明文字。

修改派生结果不得反向修改原始事实。

## 归属区间

区间边界按以下优先级确定：

1. 管理员明确设置的人工起点；
2. 官方 `reset_at` 变化形成的新窗口；
3. 当前官方窗口的自然起点。

同一 `reset_at` 内百分比明显回退与官方窗口证据冲突，应先排除该观测，等待窗口更新或管理员处理。首个 0% 观测可作为真实成本基线。

算法输入统一归一化为区间起点的 0 美元、0% 和 0 小时。没有真实 0% 观测时，可以根据已确认的官方或人工边界构造计算用零点；该零点是派生输入，不写成伪造的原始观测。

## 成本坐标

Sub2API 的累计统计按自然日期查询；日期变化时，累计值可能更换起点。不同查询起点的两个累计值不能直接相减。每条新采样因此同时保存：

- 原始累计值与实际查询窗口；
- 上一采样至当前采样的标准、实际成本增量及来源；
- 按区间增量衔接得到的官方周期累计值。

百分比观测被排除时，只停止使用该点的百分比证据；其成本区间仍参与后续累计值重建。旧数据可在“数据维护”中只读请求日志补建成本区间。普通“重建全部结果”不会请求 Sub2API，只有显式的历史补全与成本重取会读取历史日志。

## 参与者与未解释成本

每个区间以该区间出现过的 Sub2API 用户并集构建成本轨迹。尚未绑定的用户和无法映射的总成本差额进入“未解释主体”：

- 参与总进度推断；
- 没有合同权益；
- 不生成余额建议；
- 以后完成用户绑定时可以从原始历史重放。

用户成本之和低于总成本时，正差额进入“未解释主体”；用户成本之和高于总成本时不缩放用户原始轨迹，只把负差额写入诊断。

Sub2API 偶发修正累计值时，模型输入对总成本、各用户成本和未解释成本分别取单调包络，避免“下降后恢复”被重复计算。原始值保持不变；包络修正金额和主体数写入模型诊断。

## 重放

新增末尾观测也会从当前区间起点重建，因为粒子状态依赖完整区间；历史插入、人工起点、排除、恢复、用户补建或算法升级从最早受影响边界向后重放。

粒子滤波包含随机采样，随机种子必须由稳定事实生成，不得依赖当前时间或进程状态。建议种子输入至少包含：

```text
算法版本 + 账号 ID + 区间起点
```

完整重放与逐条追加必须产生相同派生结果。

## 算法版本

每条观测只在派生事务成功后保存算法版本；待计算或旧版本记录由启动检查继续重放。历史重放不发送通知，也不调用 Sub2API 写接口。重放改变当前建议值时，旧建议的“已应用”状态不再阻止新建议展示。

## 成本口径

实际成本、标准成本和 FAST 修正先形成模型无关的规范成本轨迹，然后才交给平均恒定或时变模型。切换成本口径，以及修改安全系数、初始值或建议阈值时，会在同一设置事务中重放派生结果；失败则回滚设置。两套原始成本始终不变。
