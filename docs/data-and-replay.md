# 数据与重放

本文定义额度算法可读取和可改写的数据边界。

## 保留证据

以下数据无法从历史请求日志恢复，额度算法和历史重建均不得修改：

- 观测时间、账号 ID、官方窗口时长和重置时间；
- 上游返回的整数已用百分比；
- 当时读取的用户余额；
- 管理员设置的人工起点、排除和恢复操作。

## 可重取事实

以下事实来自 Sub2API 请求日志。正常采样会保存快照；历史维护则以日志为
权威来源覆盖旧快照，不使用旧累计值作为正确性门槛：

- 账号的标准成本、实际成本和相邻观测增量；
- 每个 Sub2API 用户的累计成本和区间增量；
- FAST 请求及按用户汇总的修正事实；
- 由上述事实生成的参与者成本轨迹。

历史用户余额没有对应的时间点查询接口，重建时只保留数据库中已经采集到
的余额，不推测缺失值。主要载体是 `Observation`、
`Sub2APIUserUsageSample`、`ObservationFastCorrection` 及
`ParticipantSnapshot.raw_*`。

## 派生结果

归属区间、额度折算、参与者权益与建议、概率范围和模型诊断均可随算法版本
重新生成。修改派生结果不得反向修改保留证据。

## 归属区间

区间边界按以下优先级确定：

1. 管理员明确设置的人工起点；
2. 官方 `reset_at` 变化形成的新窗口；
3. 当前官方窗口的自然起点。

同一 `reset_at` 内百分比明显回退与官方窗口证据冲突，应先排除该观测，等待窗口更新或管理员处理。首个 0% 观测可作为真实成本基线。

连续 0% 是尚未产生消费的空闲阶段，不足以证明出现了多个周期：原始采样全部保留，但派生账本只保留最后一个 0% 作为候选基线；首次出现正百分比后，再以该点的 `reset_at` 确认区间。这样既不会用漂移的预计重置时间制造空周期，也能使用最接近首次消费的零成本基线。

算法输入统一归一化为区间起点的 0 美元、0% 和 0 小时。没有真实 0% 观测时，可以根据已确认的官方或人工边界构造计算用零点；该零点是派生输入，不写成伪造的原始观测。

## 成本坐标

Sub2API 的累计统计按自然日期查询；日期变化时，累计值可能更换起点，不同
查询起点的累计值不能直接相减。实时采样会同时保存累计快照、实际查询窗口
和相邻增量。历史全量重建不再依赖这些旧快照：它按每条记录的官方窗口起点
和时间，从请求日志重新汇总账号及逐用户成本，再重算 FAST 修正与派生结果。

百分比观测被排除时，只停止使用该点的百分比证据；其请求日志成本仍参与
后续累计值。数据维护页面的“重建全部历史”是唯一会覆盖历史成本事实的入口。

## 参与者与未解释成本

每个区间以该区间出现过的 Sub2API 用户并集构建成本轨迹。尚未绑定的用户和无法映射的总成本差额进入“未解释主体”：

- 参与总进度推断；
- 没有合同权益；
- 不生成余额建议；
- 以后完成用户绑定时可以从原始历史重放。

用户成本之和低于总成本时，正差额进入“未解释主体”；用户成本之和高于总成本时不缩放用户原始轨迹，只把负差额写入诊断。

Sub2API 偶发修正累计值时，模型输入对总成本、各用户成本和未解释成本分别取单调包络，避免“下降后恢复”被重复计算。普通重放不改写来源成本；显式历史重建可用请求日志替换旧快照。

## 重放

新增末尾观测会从当前区间起点重放；历史插入、人工起点、排除、恢复或算法升级从最早受影响边界向后重放。历史全量重建则先重取所有可恢复事实，再从第一条百分比观测重放。

粒子滤波包含随机采样，随机种子必须由稳定事实生成，不得依赖当前时间或进程状态。建议种子输入至少包含：

```text
算法版本 + 账号 ID + 区间起点
```

完整重放与逐条追加必须产生相同派生结果。

## 算法版本

每条观测只在派生事务成功后保存算法版本；待计算或旧版本记录由启动检查继续重放。历史重放不发送通知，也不调用 Sub2API 写接口。重放改变当前建议值时，旧建议的“已应用”状态不再阻止新建议展示。

## 成本口径

实际成本、标准成本和 FAST 修正先形成模型无关的规范成本轨迹，再交给平均恒定或时变模型。切换成本口径及模型参数时只重放派生结果；数据维护中的历史全量重建才会重新读取并覆盖两套来源成本。
