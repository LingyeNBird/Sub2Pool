# Sub2API 上游计费与历史兼容

## 设置与写入范围

系统设置中的“Sub2API 上游计费”直接管理 Sub2API v0.2.1 的分组计费配置，不再修改本地历史修正规则。CPA 继续使用独立计费体系，不参与本次切换。

| 设置 | 写入方式 |
| --- | --- |
| FAST 目标倍率 | 按模型匹配写入分组价格卡的 `fast_multiplier`，例如直接写入 2.5，而不是在本地乘 2.5 / 2 |
| 模型倍率 | 从接管前价格、可解析的渠道价格或上游价格目录解析基础价，再写入倍率后的绝对 Token 价格；重复应用不叠乘 |
| 长上下文阶梯计费 | 分组级 `long_context_pricing_enabled` 三态：开启、关闭、不接管；不再提供本地模型阈值或源/目标倍率 |

模型规则按顺序首次匹配，不区分大小写，支持精确名称及末尾 `*`，每类最多 100 条，倍率范围 0.01–100。空规则表示不接管该项；已接管后清空规则并应用，会恢复对应的接管前值。长上下文开关作用于整个分组，不是旧版本的按模型修正。

新部署默认 FAST 规则依次为 `gpt-6* → 2`、`* → 2.5`：GPT-6 系列使用 2 倍，其余模型使用 2.5 倍，不叠加。普通模型倍率仍为 `gpt-6* → 1.8`，默认关闭长上下文阶梯计费。

卡片上只编辑计费规则。点击“写入 Sub2API 分组计费”后，弹出的模态框自动读取 OpenAI 分组；勾选后点击“确认写入”，取消或未选分组均不提交。选择随应用保存，账号关联关系不会扩大写入范围，也不要求目标已被监控。**修改会影响所选分组内所有用户。** 取消勾选不撤回旧配置；操作日志保留，撤回仍恢复所有被接管分组。只写入 `model_pricing`、`long_context_pricing_enabled`、`free_openai_fast`，不修改分组倍率或其他管理字段。

价格卡保留未命中规则及其他价格字段。可直接处理的平坦渠道价格可以复制到分组；复杂区间/时间计价、不能保持原语义的通配符覆盖等情况明确失败，不用猜测价格代替。已有统一 FAST 通配符可保留覆盖范围；依赖目录展开的模型规则只覆盖当次能够解析的模型，上游新增模型后应重新应用。免费 FAST 与局部接管冲突时也会拒绝写入。

三个标题右侧各有独立的“查看当前”：模态框顶部按分组列出标签，只显示对应的 FAST、模型倍率或长上下文配置；各自保留选择和读取状态，切换标签不会让较早响应覆盖当前分组。查看是只读操作，不使用未提交的表单值。FAST 显示原始倍率及免费开关，未设置不冒充 1 倍；长上下文显示上游开关。上游模型价卡保存绝对单价，模型倍率按明确标注的接管前分组价或当前渠道/目录基础价比较；不包含用户/分组折扣，无法得到统一倍率时展示分项比值、单价和原因。

FAST 和模型视图每页显示 10 条，复用上一页/下一页控件，支持不区分大小写的模型名称/匹配规则搜索。搜索覆盖当前分组全部已读取条目，不额外请求上游；搜索或切换分组回到第一页。显式设置项排在继承项之前：FAST 判断是否设置倍率，模型判断是否设置任意价格字段（0 值也算设置）；不会仅因倍率为 1 就误判为继承。两类视图的搜索和页码互相独立，长上下文展示不变。

FAST 和模型设置说明收纳在标题旁的问号提示中，“查看当前”紧接标题，“添加规则”位于同一行右侧；长上下文的“查看当前”同样紧接标题。当前值弹窗不再重复展示只读说明及搜索下方的统计说明。底部统一显示“共 X 条 · 第 Y / Z 页”，包含单页和空搜索结果。

模型查看不会为只改 FAST、没有改变基础单价的价卡逐个查询目录；这些价卡直接显示未额外调价。确需补充的参考价按模型去重，最多 8 个并发读取，不引入跨请求的陈旧价格缓存，也不改变写入路径或提高超时。

## 升级与自动尝试

迁移 `0054_upstream_pricing_cutover` **不联网**：

- 冻结升级前的六项本地修正设置，将已有 Sub2API 观测标为 `local` 并保存其冻结规则。
- 记录本地计费切换时间，保留原始观测、请求事实和已有历史金额；CPA 标为不参与修正。
- 从旧设置生成待应用的上游策略；无法表达的旧长上下文目标不会静默近似，记录失败并等待管理员调整。
- 清除旧计费公告的已读记录，替换为本次动态计费公告；保留非计费的自动应用额度公告。

迁移 `0055_upstream_pricing_group_selection` 增加手动选择：保留已有操作日志中的目标作为当前选择，未接管的安装保持空选择。未选择时监控进程不会自动写入；管理员必须先选择并确认应用。已有尝试时间仍持久化，失败或部分成功不在每次启动时重试。迁移不联网；更换连接地址会清空选择，避免同一 ID 被误用于另一服务。

迁移 `0057_gpt6_fast_default` 为旧上游目标策略补入 `gpt-6* → 2`，放在覆盖 GPT-6 的宽泛规则之前，保留更早的精确模型规则和其他配置。已有 `gpt-6*` 自定义规则、主动清空 FAST 规则、已达到 100 条规则上限的配置保持不变。迁移只执行一次，不修改冻结的本地历史规则、不改上游价格或撤回日志、不重置公告入口。若原策略为“已应用”，补入后改为“等待应用”并提示管理员确认写入；保留原应用时间和账号实际计费状态，不能把新目标冒充为已生效计费。

### 公告快捷操作

计费公告提供主题色“一键应用修正”，复用设置页的分组选择模态框，默认不勾选分组。确认后只向勾选分组写入固定推荐策略：GPT-6 系列 FAST 2 倍、其他模型 FAST 2.5 倍、`gpt-6*` 模型 1.8 倍、关闭长上下文阶梯计费；不使用未保存草稿，也不把当前自定义策略冒充推荐策略。

迁移 `0056_pricing_announcement_action` 只新增持久化时间 `announcement_applied_at`，不联网、不自动写入。取消、读取分组失败、空选择或未通过前置校验不消耗入口。确认请求被服务端接受后，在现有全局操作租约内保存消费时间，所有管理员的公告入口永久隐藏；刷新、重启、标记已读、撤回均不恢复入口。即使应用失败或部分成功也已消耗，设置页仍可核对分组结果、修改策略并重试。重复公告请求被服务端拒绝，不能仅靠刷新页面再次执行。

公告“撤回上游计费配置”长期保留，无可撤回配置时禁用，后续从设置页应用后仍可再次撤回。自动应用建议额度公告提供主题色“一键开启”，通过既有设置接口开启 `auto_apply_recommendations`，同步设置页开关但不覆盖其他草稿；已开启时显示禁用的“已开启”。此操作仅开启后台自动应用，不立即强制修改任何参与者余额；在设置页关闭后，公告可再次一键开启。

## 确认、失败与撤回

每次写入前持久化接管前值、最近确认值、待写值及操作状态；写入后重新读取上游确认。跨分组操作不是上游事务：一个分组失败时保留其他分组的真实结果，页面与公告显示失败或部分成功，不宣称全部生效。

发生超时等不确定结果时保留写入日志，重试和撤回可以核对当前值。上游字段若已被其他管理者改为日志之外的值，操作报冲突，不覆盖外部修改。相同策略再次应用不会重复乘价，也不会无故切换已确认的计费时期。

“策略版本”（`revision`）是当前上游计费操作状态的递增编号，不是历史版本库。通过前置校验后进入应用或撤回操作便递增，因此失败尝试也可能产生新编号；只编辑草稿、查看当前值不会递增。撤回请求必须携带当前编号，旧页面或旧公告的编号会被拒绝。撤回恢复接管前配置，不支持任意选择历史版本、版本差异比较或逐版本回滚。计费时期标识会使用该编号建立观测分段，但价格未变化的重复应用可保持原计费时期。

设置卡片和公告都可“撤回”：恢复本服务接管前的三个计费字段，不是写入所谓默认价。撤回同样逐组确认，失败可重试。**撤回不会重新启用本地修正，也不会再次自动应用。** 完整撤回后，之后的明确应用会重新接管；更换上游地址前应先处理原地址上仍被接管的配置。

## 历史与新观测

| `correction_source` | 含义 |
| --- | --- |
| `local` | 升级前历史；使用观测保存的冻结规则计算、展示及补算 |
| `upstream` | 采样时账号全部关联分组都在当前选择中且已确认成功；只选择部分分组时，不把整个账号标为已修正 |
| `none` | 尚未确认、应用失败、撤回后或 CPA；不额外修正，不显示“已修正” |

新的请求捕获仍保留原始实际/标准成本、模型、服务档位、Token 和上下文计费事实，但不再生成本地 FAST、长上下文或模型修正额。计费时期改变时建立新的测算分段，避免把不同价格时期的累计金额直接相减。已有观测保留其采样时来源，不随之后的应用或撤回改写。

历史本地计算仍按 FAST → 长上下文 → 模型倍率顺序进行，使用 Decimal 和逐阶段舍入；负修正保留。规则来自该条观测的冻结快照，不来自当前设置。API Key 历史请求使用切换时间前的冻结策略，切换时间后的请求使用原始成本。更改上游策略不会重算旧历史。

只有旧 FAST 汇总而无完整请求的区间继续保留原值并标注证据不足。管理员可以通过原有 `/fast-correction/calculate` 路由显式补采该历史区间；补采使用冻结规则、事务写入和受影响后缀重放。失败不清空旧值，完整捕获不会被覆盖，缺失事实不凭空构造。新 `upstream`/`none` 观测不允许走本地补算。

## 余额建议的扣费口径换算

容量与权益测算继续使用选定成本口径，余额建议换算为钱包实际扣费口径。换算系数是同期实际成本 / 测算成本，优先本人样本，无本人样本时采用同账号样本。各来源分别换算带符号净头寸，再汇总、应用安全系数及舍入。

历史样本使用冻结后的本地修正；新样本不叠加本地修正。即使没有本地修正，选择标准成本时仍可能需要标准成本到实际成本的换算。页面、通知和应用共用同一钱包金额，不重复换算；这仍是基于历史消费结构的估计，不保证未来模型和服务档位分布不变。

## 管理 API 与数据保留

- `GET /api/settings/upstream-pricing`：策略、`selected_group_ids`、逐组结果、时间、错误与可撤回状态。
- `GET /api/settings/upstream-pricing?groups=1`：读取可选 OpenAI 分组；只读，不改变选择。
- `GET /api/settings/upstream-pricing?group_id=7&kind=fast`：只读指定分组当前配置；`kind` 为 `fast`、`model` 或 `context`，响应只包含该类别。模型视图必要时读取渠道与模型目录参考价，不写入上游或本地策略。
- `POST /api/settings/upstream-pricing/apply`：提交 `policy`、非空正整数数组 `group_ids` 与 `confirm: true`。缺少选择会被拒绝，不回退到账号关联分组。
- 公告调用同一应用接口，额外提交 `announcement: true`，服务端固定使用推荐策略，不需要提交 `policy`；状态响应包含 `announcement_applied_at`。公告列表返回 `can_apply_pricing`、`can_revert` 及自动应用建议额度的当前开关值。
- `POST /api/settings/upstream-pricing/revert`：明确确认后恢复接管前值。
- 旧六项本地修正字段不再通过设置 API 修改；旧字段写入请求会被拒绝。

`ObservationBillingCapture`、`BillingUsageFact` 和 `APIUsageRequestFact` 继续保存不可变原始事实。API Key 原文、请求内容和凭据不会进入这些请求事实表。原始捕获会占用数据库空间，应纳入备份容量规划。回退代码前保留升级前备份和当前数据库副本，不在唯一生产数据库上反向迁移删除新事实。

## 隔离验证

后端回归使用临时 SQLite 与合成 `httpx.MockTransport`，覆盖部分成功、重试、不叠乘、外部冲突、撤回、冻结历史以及计费分段。迁移检查不需要真实上游。

`scripts/billing_browser_smoke.py` 每次创建新的合成数据库，并运行本机假 Sub2API 与真实 Django/Vue 页面，覆盖写入失败重试、历史补算和公告撤回。`scripts/billing_rule_layout.py` 检查 320–1440px 下输入控件可用范围以及规则增删排序。演示站只模拟这些操作，不会修改真实 Sub2API。CI 上传截图和检查结果，不上传数据库或凭据。
