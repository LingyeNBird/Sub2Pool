# CPA 拼车

CPA 复用 Sub2Pool 的系统用户、参与者和额度池。一个参与者可以只绑定 CPA Key，也可以同时绑定一个 Sub2API 用户；一个人可持有多个 CPA Key。两个渠道的额度池、权益和余额分别计算。

## 配置流程

1. 在系统设置中配置 CPA Management API 和 usage 订阅连接，添加监控账号。
2. 在参与者页面添加成员；只用 CPA 时，Sub2API 用户选择“仅使用 CPA”。
3. 切换到 CPA，选择成员后绑定已采集的 Key，或输入完整 Key 预先绑定；可以填写、修改 Key 备注。
4. 在额度分配中切换到 CPA，设置独立池或多个 CPA 账号组成的混池，以及各成员份额。池内份额合计不能超过 100%，不得跨渠道混池。
5. 在系统用户页面创建登录账号，授权对应参与者、CPA 账号及总览／参与者／统计等页面。普通用户同时满足账号授权和池成员关系才能查看该池。

绑定从提交时刻生效；解除绑定只关闭归属时间区间，过去的请求仍归原成员。原始 Key 仅用于计算现有 HMAC 摘要，不写入数据库、spool 或返回值。末四位相同的 Key 仍由完整摘要区分。

## 车主身份与未匹配 Key 的请求

复用参与者编辑中的“设为车主”，不按姓名识别，也无需另外指定车主。每个 CPA 池中只有一位启用的车主时，该池各账号从身份或份额配置生效时刻起，将没有匹配到成员 Key 的请求（包括没有 Key 的已采集请求）归给车主。已有 Key 绑定和已确认的历史认领优先；同池没有车主或存在多位车主时暂停默认归属，并在账号卡片提示。

身份取消、停用或池成员调整会关闭旧归属区间；新车主只接收其生效后的请求。旧归属记录保留，迟到请求按发生时间匹配。升级会根据现有车主身份建立从升级时刻开始的归属区间，不自动追溯修改历史。

要把升级前的未归属请求计入车主，在额度总览选择 CPA 账号，在账号卡片点击“认领历史未归属请求”。预览目标由该池车主身份确定，包含该账号所有已采集且未归属的历史请求、Token、估算费用、缺价与采集缺口；确认后写入认领记录并重算。仅认领预览中的已有事实，重复确认不会重复计数；迟到的更早请求需要重新认领。其他成员的已归属请求不会被认领。完全绕过 CPA、没有被采集的调用无法生成逐次请求明细。

## 历史请求认领

绑定后可打开“历史认领”，选择参与者、开始时间和结束时间，先预览请求数、Token、费用、未计价请求和采集缺口，再确认认领。范围采用 `[开始, 结束)`；默认结束时间精确衔接当前绑定的生效时间。

预览有效期为 15 分钟，冻结请求事实、Key 归属、价格配置、观测和额度池合同。确认时若这些数据变化，需要重新预览。重复确认已完成的预览不会重复归属。时间范围不能与常规绑定或其他参与者的认领重叠；同一参与者可在原范围再次预览，只认领新收到且尚未归属的请求。

认领仅新增归属记录和确认时的事件清单并重算派生额度，不修改 `CPAUsageEvent`。确认后迟到的历史请求不会自动加入认领，需再次预览确认。断线时未采集的请求不会补造。当前份额不会被追溯到历史；历史合同缺失时可以查看请求与消耗，历史剩余权益保持未知。有 Key 归属、认领计划或 CPA 合同历史的参与者只能停用。

## 展示口径

- 总览、参与者和统计页面为所有 CPA 池成员展示额度卡片，普通用户自己的卡片排在前面，管理员也能看到所有成员卡片。卡片显示合同份额、已采集请求费用与用量，以及可计算时的权益总额、已用权益、剩余权益和超额状态。多账号池可在卡片内切换账号；进度条以该成员的合同份额为 100%。汇总表可展开查看。
- “数据不足”卡片保留已采集用量，并列出采集缺口、缺价、无额度观测或历史份额依据不足等原因，不将未知剩余额度画成零。认领和补价不能恢复漏采请求，需要后续完整周期具备有效观测与合同依据后才可估算剩余。
- 个人 Key 的费用轨迹接入现有平均恒定／时变模型；未绑定 Key 的消耗保留在未归属主体中，不分摊给成员。成员在 CPA 的重放不会改动其 Sub2API 全局余额。
- 多账号池分别依据各账号的上游重置周期计算，再汇总等效美元权益。仅授权部分账号时明确标注部分范围，不暴露其他账号用量。
- 请求费用按当前本地模型价格重算，不代表 CPA 可扣减余额。未知模型保留请求数和 Token，同时标明未计价；它及采集缺口、有效观测不足会阻止展示可靠剩余额度。
- 请求更新时间和额度观测时间分别显示。usage 尚在 spool 或采集器未连接时会提示数据延迟。
- 普通用户能看同车成员汇总，只能看本人授权参与者的 Key 分项和逐次请求。管理员可看全部。逐次请求包含模型、Token、费用、成功／失败、请求标识、耗时和首 Token 延迟，不包含对话正文。
- 当前仅展示额度和超额提示，不会停用 Key 或拦截调用。

## 请求明细与一键补价

请求明细页的“成员额度”入口携带当前账号返回总览；卡片区提供“我的请求明细／查看请求明细”“分配 CPA 份额”和 Key 管理入口。

侧边栏“CPA 请求明细”提供独立请求页面，沿用系统用户的“额度统计”页面授权。选择 CPA 账号后，可按时间、模型、本人 Key、成功／失败筛选；摘要统计整个筛选范围，列表支持每页 25／50／100 条。移动端使用卡片列表，“详情”展示完整请求标识、Token 和耗时。统计页顶部的“请求明细”会携带当前账号跳转到独立页面；“模型价格”对管理员开放。缺价提示中的“一键同步缺失价格”会打开价格窗口并开始同步，也可以先打开“模型价格”查看缺价模型及其请求数，再决定同步或手动填写。

价格窗口统计所选账号的全部已采集请求（从系统设置打开时统计全部账号），不受统计页日期筛选限制。价格配置全局共享，保存后所有 CPA 账号的历史请求费用和派生额度都会重算；原始请求保持不变。同步和重算在同一事务内完成，失败则保留原价格。

同步从 `https://models.dev/api.json` 下载公共目录，在本地匹配 OpenAI 模型名称，不发送 Key、请求内容或用量。只补齐已有请求缺失的输入、缓存输入、输出三项基础价格，保留已有手动价格；FAST 和长上下文计费继续使用当前 CPA 配置。目录未收录的名称、自定义别名或缺少完整三项价格的模型仍显示缺价，可手动输入。未知价格不会自动设为零。

升级后请刷新已打开的浏览器标签页，加载新版前端。

## API

所有路径以 `/api` 为前缀。管理接口使用管理员 JWT；只读接口还提供 `/v1/cpa/summary` 和 `/v1/cpa/requests`，使用 Sub2Pool 个人或管理员 API Key，执行相同的数据范围限制。CPA 调用 Key 不作为面板登录凭据。

| 方法与路径 | 用途 |
| --- | --- |
| `GET /settings/cpa-pricing?account_id=...` | 管理员查看价格和已采集缺价模型；省略账号时统计全部 CPA 账号 |
| `POST /settings/cpa-pricing?account_id=...` | 管理员一键补齐缺价模型并重算，返回已添加和无法匹配的模型 |
| `GET /cpa/keys` | 管理员读取已登记 Key、绑定区间和未登记的已采集 Key |
| `POST /cpa/keys` | 提交 `participant_id`、可选 `name`，以及二选一的 `raw_key`／`observed_hash` |
| `PATCH /cpa/bindings/{id}` | 修改 Key 的 `name` 备注 |
| `DELETE /cpa/bindings/{id}` | 幂等结束当前绑定，保留历史 |
| `POST /cpa/unassigned/preview?account_id=...` | 管理员预览该账号未归属历史请求，认领目标由当前车主身份确定；确认复用 claims/{id}/apply |
| `POST /cpa/claims/preview` | 提交 `key_id`、`participant_id`、`started_at`、`ended_at`，返回预览和计划 ID |
| `POST /cpa/claims/{id}/apply` | 确认认领预览，重算受影响账号 |
| `GET /cpa/summary?account_id=...` | 返回该账号所属池在调用者授权范围内的成员汇总 |
| `GET /cpa/requests?account_id=...` | 查询本人／管理员可查看的请求 |

请求查询支持 `include_summary=true`（返回整个授权筛选范围的 Token、费用、成功／失败数及有效耗时均值）、`days`（1–90，省略开始时间时回看天数），以及 `participant_id`、`key_id`、`model`、`failed`、`started_at`、`ended_at`、`page`、`page_size`。默认最近 7 天，最多 90 天；默认每页 50 条，最多 100 条，按请求时间和 ID 倒序。返回的 Key 和模型选项也按调用者权限过滤。

CPA 汇总的成员新增 `is_owner`；账号新增 `owner`（参与者 ID、名称、生效时间和 active／missing／ambiguous 状态）。账号和成员账号分项均返回 `quota_unavailable_reasons`。车主历史认领返回 `key_id: null` 和对应的 `account_id`。

`GET /quota-allocation?provider=cpa` 读取 CPA 分配；`PUT /quota-allocation` 的请求体增加 `provider: "cpa"`。省略渠道时仍处理 Sub2API，保存一个渠道不会删除另一个渠道的分配。参与者的 `sub2api_user_id` 现在允许为 `null`。

## CPA 账号状态与额度重置

账号状态页中，CPA 账号展示请求数、Token、估算费用、成功率，以及上游提供的周限额、短时限额、代码审查和附加模型限额。进度条表示**剩余比例**；窗口卡片同时标注重置时间、观测时间和边界依据。总体统计最多回看 30 天，以页面标出的时间范围为准；窗口用量只计入本系统已采集的请求。

标准窗口展示上个窗口、当前窗口和预测。当前窗口的结束时间是上游重置时间，已用请求统计截至本次查询时间。只有采集完整、请求均已计价、已用比例有效且大于零、模型范围可确定时，才按已用比例线性估算满额总量。附加限额范围不明确时，标准窗口展示该时间段的账号合计并停止预测；附加窗口仅显示上游比例和重置时间。提前重置的历史窗口只展示截断区间，不作为预测依据。金额为估算值，不等于成员合同余额。

**只有管理员或对应 CPA 池的车主可以重置额度。** 车主由参与者的“设为车主”身份确定，必须是池中唯一启用的车主，并且登录用户已获该参与者、账号和账号状态页面的授权。普通成员可以查看汇总，不能调用重置接口；修改账号或预览 ID 也不能绕过授权。权限在提交时再次检查。

点击“重置额度”只读取可用次数并打开确认弹窗。弹窗标明账号、当前可用次数和将消耗 1 次、成功后不可撤销，用户必须再点“确认消耗并重置”。预览有效期为 5 分钟。没有次数时按钮禁用；上游未返回可靠次数时显示“未知”，不能发起新重置。

同一账号的重置串行执行；确认前持久化重置标识，重复提交已成功请求不会再次调用上游。响应丢失或结果未知时保留原请求，使用“核对重置结果”重试同一标识，管理员也可处理车主留下的待核对请求。上游明确拒绝时显示失败记录，可检查账号和 CPA 版本后重新预览。重置记录只包含从本系统发起的操作，最近展示 10 条，不代表上游全部历史。

页面使用 JWT 接口：

| 方法与路径（`/api` 前缀） | 用途 |
| --- | --- |
| `GET /account-status` | CPA 账号增加 `cpa_quota`，包含 totals、windows 和 reset |
| `POST /account-status/cpa/{account_id}/reset-preview` | 获取待确认计划及可用次数，不消耗额度 |
| `POST /account-status/cpa/{account_id}/resets/{id}/confirm` | 请求体必须为 `{ "confirmed": true }`，确认或核对原计划 |

外部只读 API 同步提供 `cpa_quota` 读取结构，不提供重置写接口。迁移 `0055` 增加重置审计记录，不修改原始请求、份额或 Sub2API 余额。

## 升级与后续

迁移保留参与者 ID、已有授权和所有原始 CPA 请求，不自动认领历史。现有 Sub2API 参与者无需重新配置。第一次使用 CPA 拼车时按上述流程添加绑定与份额。

### 部署当前 CPA 分支

本次功能位于 `https://github.com/ld0574/Sub2Pool` 的 `cpa` 分支。该分支的推送不会自动发布镜像；README 中的上游 `ghcr.io/lingyenbird/sub2pool:latest` 不保证包含这次改造。当前可从源码构建。

全新安装：

```bash
git clone --branch cpa https://github.com/ld0574/Sub2Pool.git sub2pool
cd sub2pool
cp .env.example .env
# 编辑 .env：设置随机 DJANGO_SECRET_KEY、管理员密码和域名/IP。
docker compose up -d --build
docker compose logs --tail=100 app
```

已有源码部署：在原部署目录中更新到本仓库的 `cpa` 分支，再执行 `docker compose up -d --build`。保留原 `.env`、Compose 项目名和数据卷挂载；不要重新生成已有实例的 `DJANGO_SECRET_KEY`，加密配置和 CPA Key 摘要依赖它。

已有 GHCR 部署：先在另一个目录构建本地镜像，然后在原部署目录增加覆盖文件，以沿用原实例的数据卷和环境变量：

```bash
git clone --branch cpa https://github.com/ld0574/Sub2Pool.git sub2pool-cpa-src
docker build -t sub2pool-cpa:local ./sub2pool-cpa-src

# 以下命令在原来存放 compose.yaml 和 .env 的部署目录执行。
cat > compose.cpa.yaml <<'YAML'
services:
  app:
    image: sub2pool-cpa:local
    pull_policy: never
YAML

# 停止写入后备份整个数据目录，包含主数据库和 CPA spool。
backup_dir="./backup-cpa-$(date +%Y%m%d-%H%M%S)"
mkdir -p "$backup_dir"
docker compose stop app
docker compose cp app:/app/data/. "$backup_dir/"
docker compose -f compose.yaml -f compose.cpa.yaml up -d --no-build
docker compose -f compose.yaml -f compose.cpa.yaml logs --tail=100 app
```

源码升级也应在重建前使用上述停止与备份命令。若原部署使用额外的 `-p`、`--env-file` 或其他 Compose 文件，升级命令继续使用相同参数。后续使用本地镜像部署时，继续带上 `-f compose.cpa.yaml`。

容器启动脚本会自动执行 `migrate`（包括 `0052`、`0053`、`0054`、`0055`）、历史重放及管理员初始化，无需手工进入容器迁移。首次升级的历史重放可能延长启动时间，可通过日志确认完成，再访问 `http://服务器IP:8088`（或原访问地址）。升级后按本文配置流程设置 CPA 成员、Key、份额和系统用户授权。

第二阶段再验证目标 CPA 版本的 Key 控制能力，选择直接控制或请求网关，实现超额自动限制。

## 周额度与订阅账期累计权益

CPA 拼车汇总在额度总览、参与者和统计页同时展示本周分布、订阅账期分布与成员卡，不需要切换周／月。多个账号分别展示周条形图，账期只累加当前用户获授权账号的美元值。姓名和颜色在图表、图例和成员卡之间保持一致。

管理员通过「订阅账期累计分布 → 配置订阅账期」设置订阅起始日期和 IANA 时区（例如 `Asia/Shanghai`）。不填写月预算；31 日续期的订阅在短月取月末，下个月恢复 31 日。尚未配置时不猜测续费日，也不自动认领历史请求。设置可随时修改或清空，成员没有写权限。

### 计算口径

- 账期预计容量按真实上游周期累计。时变模型直接复用粒子轨迹的持久化容量估计及 90% 区间；平均恒定模型沿用其容量计算。历史取最后可靠估计，当前取最新可靠估计；未来自然周期优先用当前估计，否则用最近三个可靠已结束周期的中位数。
- 同一官方重置时间内的断线、重连或归属分段不会重复产生容量。提前手动重置截断旧周期，旧、新周期都计入完整容量；跨账期按周期实际区间的重叠秒数分摊。
- 请求费用按实际发生时间计算，使用现有 CPA 模型价格和历史 Key／车主／认领归属。历史账号所属池与个人份额来自 `CPAQuotaContract`，份额变化按生效时刻分段，不用当前份额补造历史合同。
- 完整采集的已结束周期，失效额度为估算容量减该周期全部已计价消费的正值，再按账期重叠比例分摊。失效额度不进入后续可用量。
- 个人预计剩余权益为账期预计权益减累计消费，可为负。分别显示本周超份额、已结束周期累计多用、整个账期预计超额。
- 后续建议总量受当前未失效余额与未来预测容量约束，按正的剩余权益比例分配，同时为未分配权益和其他历史成员保留空间。建议不超过个人正的剩余权益，也不写入份额、不限制请求、不修改 Sub2API 余额。
- 三人各占三分之一、四周容量均为 $1,000、第一周 A/B/C 消费 $500/$250/$250 时，A 后续建议总量约 $833.33，即后三个周期平均 $277.78、27.8%。

容量时间分摊与请求发生时间统计是两种口径。跨账期时，消费与容量不强行平账；图表保留原始百分比，超出 100% 会标注，不能缩小比例掩盖超额。累计消耗条的留白表示未展示为消费的理论容量，实际可用量以「当前及后续预计可用」为准。

粒子容量估计不要求从官方周起点连续采集。重连后的有效模型区间也可提供容量、估计区间和成员使用百分比；仅有模型初始值时标注“先验估计”，完全没有模型观测时保持未知。容量估算时间与请求统计时间分别显示。补价或延迟事件改变区间成本后，旧结果须通过成本一致性校验才能继续使用；刷新成本并重放后显示更新后的估计。

采集缺口或缺价不隐藏已有容量估计，但完整个人剩余、失效量与后续建议仍返回 `null`。成员卡可按当前份额展示本周参考预算及已采集消耗占比，不能用它补造历史权益。账期周期边界与历史合同明确时，可继续显示预计权益；缺少这些依据时相应总量或权益仍未知。保留已采集金额及明确的上游剩余比例，图表留白不等于可调用余额。未归属、其他历史成员消费和未分配权益单独列示。

### 接口与派生结果

`GET /api/cpa/summary?account_id=…` 和只读 `GET /api/v1/cpa/summary?account_id=…` 保留原字段，新增：

- `weekly_distribution`：各账号周分布、请求更新时间、容量估算时间、上游明确剩余比例、缺价数；`capacity_estimate` 提供来源、容量、区间、是否仅先验与更新时间，`coverage_complete` 表示消耗是否足以完整结算。账号状态的标准周窗口复用相同容量信息，附加模型限额不会禁用该容量展示，也不会据此虚构请求数和 Token 总量预测。
- `billing_summary`：账期配置与边界、已知实际容量、未来容量、失效量、预计可用量、质量原因、按账号拆分的周期以及各成员累计指标。
- `billing_summary.cycles[].kind` 区分 `historical`、`current`、`future`；`quota_as_of` 为实际估计或预测依据时间，`generated_at` 为本次汇总生成时间。

`PUT /api/cpa/billing-config?account_id=…` 仅管理员可用，请求为 `{"anchor_date":"2026-08-31","timezone":"Asia/Shanghai"}`；日期为 `null` 时取消配置。只读 API 不提供写入入口。

周期汇总是由已持久化 Observation、采集区间、合同与原始请求在读取时重建的派生结果，不另存可能过期的余额缓存。认领完成、价格同步和重放后，下次读取立即重新聚合；会核对可靠观测对应的请求费用，拒绝沿用补价或迟到事件导致失配的旧容量。请求定价使用每周期前缀和，避免逐个历史观测重复扫描全部请求。

### 升级

迁移 `0056` 只为额度池增加可空的账期起始日期和时区，保留参与者 ID、现有授权、归属、原始请求及 Sub2API 数据。拉取 `cpa` 分支后重新构建启动：

```sh
git pull --ff-only origin cpa
docker compose up -d --build
```

容器启动按现有流程执行迁移。首次进入 CPA 汇总后由管理员设置实际订阅账期；已有采集缺口不会因设置账期或历史认领消失。

请求列表的「模型 / 服务」、手机卡片和详情同时显示 Key 别名与末四位，例如 `Le...9x0-`（列表不再加服务等级或 Key 前缀，服务等级保留在详情中）。`CPARequest.api_key_alias` 优先返回请求中保存的 CPA `alias`，缺失时回退到本地 Key 备注；没有两者时只显示脱敏尾号 `...9x0-`。历史请求无需重新采集。此字段遵循现有本人请求权限，只读 API 同样限制。

分布图的百分比紧跟成员名称与金额，周图标注「占本周额度」，账期图标注「占账期总额度」。容量缺少可靠估计时显示「额度占比待估算」，而非省略百分比或用占已采集消费的比例替代。个人卡片的份额进度以个人份额为分母，与整车占比区分。
